01 Verified

flax==0.10.6 is incompatible with jax 0.11 — 19 test failures

requirements_tests.txt pins flax exactly; requirements.txt leaves jax at >=0.7.1. Nightly CI therefore installs jax 0.11.0, which removed jax.core.get_opaque_trace_state — a symbol flax 0.10.6 calls on every nn.Module.init. Every flax-based test dies at model construction. All 19 failures are this one exception. Nothing in tf2jax itself is broken.

P1

Structural causes and real defects

5 findings
02Verified

Unpinned jax against pinned flax and tensorflow — this will recur

jax>=0.7.1 with no ceiling, while tensorflow==2.20.0 and flax==0.10.6 are frozen exactly. A scheduled build silently drifts onto whatever JAX shipped that day against partners that cannot move with it. Finding 01 is the first casualty; it will not be the last.

Bound jax/jaxlib in requirements.txt, or pin them alongside tensorflow and let test.sh’s existing second stage track HEAD.

03Verified

XlaCallModule crashes when the platforms attr is empty

The guard is falsy for an empty tuple, so control falls through to .index() on it. _xla_call_module accepts version >= 2, and platforms postdates that — so a graph without it is a supported input that crashes with an error naming neither the op nor the attr. 

if target_platforms and jax_backend not in target_platforms:
    ...
    return None
else:
    return target_platforms.index(jax_backend)   # ().index(...) raises

Reproduced by clearing the attr on a real jax2tf-produced graph:

platforms = [b'CPU'] -> OK -> [0. 0.39733866 0.77883667]
platforms = []       -> ValueError: tuple.index(x): x not in tuple

tf2jax/experimental/ops.py:236

return target_platforms.index(jax_backend) if target_platforms else None

04Observed

Nightly failures reach nobody

ci.yml runs on cron '30 2 * * *' with no notification step, and the workflow-run filter reports 182 failed runs. Finding 01 ran unattended for months because nothing was watching.

An issue-on-failure action, or surface the scheduled run as a required signal somewhere a human looks.

05Verified

fail-fast hides the Python 3.13 job entirely

In the failing run the 3.13 job was cancelled — “The strategy configuration was canceled because build-and-test._3_12_ubuntu-latest failed.” A 3.13-only regression stays invisible until 3.12 is green.

strategy: fail-fast: false

06Verified

Actions six majors out of date

actions/checkout@v2 and actions/setup-python@v1. The runner emits a Node 20 deprecation annotation on every job, and setup-python@v1 predates version caching. pypi-publish.yml is on @v4, also Node 20.

P2

Gates switched off that pass today

2 findings
07Verified

pytype has been off since “TF 2.14”; it now reports exactly one error

test.sh disables it pending a TensorFlow 2.14 release. TensorFlow is at 2.20. Two things block a straight re-enable — the pinned command passes --use-enum-overlay, a flag current pytype rejects outright, and with that dropped the run surfaces a single error: 

tf2jax/_src/tf2jax.py:889:38: error: in _infer_relu_from_jax2tf:
    No attribute 'tolist' on tuple [attribute-error]

That one is genuine: _OpNode.__call__ is declared to return Tuple[Tuple[jnp.ndarray, ...], Mapping[...]], but ops actually return a bare array, a tuple, or the _EMPTY_RETURN_VALUE sentinel. Correcting the annotation unblocks the gate.

08Verified

pylint on the test files would pass as-is

Disabled pending pylint-dev/pylint#9185. Running the commented-out command unchanged today gives exit 24 — refactor and convention bits only — and pylint-exit -efail -wfail fails only on fatal/error/warning. It can be turned back on now.

The -d W0212,E1123,E1120 workaround is still load-bearing: without it the run is exit 26 with 169 E1120 no-value-for-parameter false positives from TensorFlow.

Suggested order

Where to start

  1. Finding 01 — the flax pin. One line, verified, unblocks everything else.
  2. Findings 05, 06, 04 — fail-fast: false, action bumps, a failure notification. Cheap, and collectively they are why 01 went unnoticed.
  3. Finding 02 — bound jax. Stops the next recurrence rather than the current one.
  4. Finding 03 — the empty-platforms crash. One line, and a real user-facing bug.
  5. Findings 07 and 08 — re-enable pytype and test-file pylint. Both pass today; 07 needs the single annotation fix first.
  6. Findings 13–18 — the small stuff. Mechanical, safe to batch.
  7. Findings 09–11 — the coverage holes. The largest genuine gap, and the one that needs design work rather than a patch.

Verified findings were reproduced or measured in a python 3.12 venv running jax 0.11.0 and TensorFlow 2.20.0, following test.sh step by step. Observed findings are static readings that were not executed.

Checked and found not to be problems, so they need not be re-investigated: int32 MaxPool matches TF exactly despite the -inf identity; test_data/** does reach the built wheel despite setuptools’ warning; setup.py --version still prints cleanly, so the release version check works; _compute_num_keys cannot leave num_keys unbound; the evaluation-cache refcount cannot free a parameter early; and jax2tf itself is not deprecated in jax 0.11 — only two of its parameters, neither of which tf2jax passes.
